Phần 1.1 — Data-Driven Testing (DDT) Là Gì?

DDT = Tách riêng logic test khỏi dữ liệu test. Cùng 1 test script, chạy với nhiều bộ dữ liệu khác nhau → mở rộng test coverage mà không cần tạo thêm request.

Không Có DDT (Thủ Công)

1. Tạo request "Chuyển 500K" → sửa body → Send

2. Tạo request "Chuyển -100K" → sửa body → Send

3. Tạo request "Chuyển 999M" → sửa body → Send

4. Tạo request "TK không tồn tại" → sửa body → Send

10 cases = 10 request × sửa tay = chậm, dễ sai!

Có DDT (Tự Động)

1. Tạo 1 request duy nhất với biến {{amount}}, {{account}}

2. Tạo 1 file CSV chứa 10 dòng dữ liệu khác nhau

3. Chạy Collection Runner → tự lặp 10 lần

4. Mỗi lần lặp, Postman tự thay biến bằng dữ liệu từ file

10 cases = 1 request + 1 file = nhanh, chính xác!

Quy tắc CSV:
  • Dòng 1 = header (tên biến) — khớp với {{amount}}, {{to_account}}...
  • Mỗi dòng sau = 1 bộ dữ liệu = 1 lần chạy (iteration)
  • Phân tách bằng dấu phẩy, không có khoảng trắng thừa
  • Encoding: UTF-8 (quan trọng nếu có tiếng Việt)
  • Nếu giá trị chứa dấu phẩy → bọc trong dấu ngoặc kép "giá trị, đặc biệt"
Mẹo: Thêm cột description và expected_status để assertions tự động so sánh kết quả!

Quy tắc JSON:
  • File là 1 mảng JSON — mỗi object = 1 iteration
  • Key trong object = tên biến trong Postman
  • Hỗ trợ đúng kiểu dữ liệu: number, boolean, null (CSV mọi thứ là string)
  • Có thể chứa nested object — phù hợp body phức tạp
Khi nào dùng JSON? Khi dữ liệu có nested object, kiểu dữ liệu quan trọng (number vs string), hoặc có field nullable.

Phần 1.3 — Map Biến Từ File Dữ Liệu Vào Postman

Header trong CSV / key trong JSON tự động trở thành biến trong Postman. Dùng cú pháp {{tên_biến}} ở bất kỳ đâu: URL, Body, Headers, Tests.

Body request — dùng biến từ file: 
{
  "from_account": "{{from_account}}",
  "to_account": "{{to_account}}",
  "amount": {{amount}},
  "description": "{{description}}"
}
Tests script — assertion động theo expected_status: 
const expectedStatus = pm.iterationData.get("expected_status");
const desc = pm.iterationData.get("description");

pm.test(`[${desc}] Status = ${expectedStatus}`, () => {
    pm.response.to.have.status(
        Number(expectedStatus)
    );
});
pm.iterationData — API đọc data file:

pm.iterationData.get("key")

Lấy giá trị của cột/key từ dòng hiện tại trong file dữ liệu.

pm.iterationData.toJSON()

Trả về toàn bộ dữ liệu dòng hiện tại dạng object.

pm.info.iteration

Số thứ tự iteration hiện tại (bắt đầu từ 0).

pm.info.iterationCount

Tổng số iterations (= số dòng dữ liệu).

Mục tiêu — Áp dụng DDT 5 bước

Tạo file CSV với 8 bộ dữ liệu, setup request dùng {{variable}}, viết assertion động — đúng quy trình 5 bước vừa học.

  • B1: Phân tích — name hợp lệ, name rỗng, ký tự đặc biệt, name cực dài
  • B2: Tạo CSV — 4 cột: name, job, expected_status, description
  • B3: Map biến — Body: {"name":"{{name}}","job":"{{job}}"}
  • B4: Test Script — kiểm tra status, id, createdAt, name khớp input
  • B5: Chạy Collection Runner — chọn file CSV, bấm Run

Tests tab trong Postman: 
const expectedStatus = parseInt(
    pm.iterationData.get("expected_status")
);
const desc = pm.iterationData.get("description");

pm.test(`[${desc}] Status = ${expectedStatus}`, () => {
    pm.response.to.have.status(expectedStatus);
});

pm.test(`[${desc}] Response co id va createdAt`, () => {
    const res = pm.response.json();
    pm.expect(res).to.have.property("id");
    pm.expect(res).to.have.property("createdAt");
});

pm.test(`[${desc}] Name khop voi input`, () => {
    const res = pm.response.json();
    const inputName = pm.iterationData.get("name");
    pm.expect(res.name).to.eql(inputName);
});

const expectedStatus = parseInt(
    pm.iterationData.get("expected_status")
);
const shouldHaveToken =
    pm.iterationData.get("should_have_token") === "true";
const desc = pm.iterationData.get("description");

pm.test(`[${desc}] Status = ${expectedStatus}`, () => {
    pm.response.to.have.status(expectedStatus);
});

if (shouldHaveToken) {
    pm.test(`[${desc}] Response co accessToken`, () => {
        const res = pm.response.json();
        pm.expect(res).to.have.property("accessToken");
        pm.expect(res.accessToken).to.be.a("string");
        pm.expect(res.accessToken.length).to.be.above(0);
    });
} else {
    pm.test(`[${desc}] Response co message loi`, () => {
        const res = pm.response.json();
        pm.expect(res).to.have.property("message");
    });
}

Phần 3.1 — Tại Sao Cần Newman?

Newman = Postman Collection Runner trên Command Line. Chạy được ở mọi nơi — kể cả server không có giao diện UI.

Postman GUI

  • Cần mở ứng dụng Postman trên máy
  • Chỉ chạy thủ công bằng tay (click Run)
  • Không tích hợp được CI/CD pipeline
  • Không chạy được trên server Linux headless

Newman CLI

  • Chạy từ Terminal — không cần giao diện
  • Tích hợp dễ dàng vào CI/CD (Jenkins, GitLab CI, GitHub Actions)
  • Chạy được trên server Linux, Docker container
  • Xuất report tự động (HTML, JUnit XML...)

Server CI/CD

Jenkins/GitLab CI chạy trên server Linux không có GUI → Newman là lựa chọn duy nhất.

Scheduled Testing

Đặt cron job chạy Newman mỗi đêm → phát hiện regression sáng hôm sau.

Team Collaboration

Share Collection JSON + Environment JSON → mọi người chạy cùng 1 lệnh Newman, kết quả nhất quán.
